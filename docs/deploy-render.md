# Deploy to Render

The API and the Angular SPA are combined into a **single web service**: Express serves
`/api/*` and also the built frontend (`index.html`), so the browser talks to one origin
and no CORS/proxy wiring is needed.

The database is a **Render-managed PostgreSQL** instance provisioned by the same
Blueprint, so nothing external is required.

## Option A — Blueprint (recommended)

1. In [dashboard.render.com](https://dashboard.render.com), click **New → Blueprint**.
2. Pick the `School-Managment-System-` repository.
3. Render reads `render.yaml` and creates:
   - a PostgreSQL database `sms-db` (free plan),
   - the `sms-api` web service, with `DATABASE_URL` wired from the database.
   The build runs `bash render-build.sh` (Angular build, then backend build).
4. Deploy. First boot creates the schema (`sequelize.sync`) and seeds defaults.

No environment values need to be filled in manually — `JWT_SECRET` and
`JWT_REFRESH_SECRET` are auto-generated and `DATABASE_URL` comes from the database.

## Option B — Manual web service

1. **New → PostgreSQL** (free) — note its **Internal Database URL**.
2. **New → Web Service**, connect the repo.
3. Name: `sms-api`; **Runtime**: Node; **Region**: same region as the database.
4. Build command: `bash render-build.sh`
5. Start command: `node backend/dist/server.js`
6. Environment variables:
   - `DATABASE_URL` = the database's Internal Database URL
   - `DB_DIALECT` = `postgres`
   - `NODE_ENV` = `production`
   - `RUN_SEEDERS` = `true`
   - `JWT_SECRET` / `JWT_REFRESH_SECRET` = any long random strings
7. Health check path: `/health`.
8. Deploy.

## Environment variables

| Key                   | Required | Notes                                        |
| --------------------- | -------- | -------------------------------------------- |
| `DATABASE_URL`        | Yes      | Injected automatically by the Blueprint      |
| `DB_DIALECT`          | No       | Defaults to `postgres`                       |
| `JWT_SECRET`          | No       | auto-generated by blueprint                  |
| `JWT_REFRESH_SECRET`  | No       | auto-generated by blueprint                  |
| `RUN_SEEDERS`         | No       | `true` runs the default seeders              |
| `RUN_JOBS`            | No       | `true` runs cron (single instance only)      |
| `REDIS_HOST`          | No       | leave blank if no Redis                      |
| `SMTP_*`              | No       | for password-reset emails                    |

Individual `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASS` (plus optional
`DB_SSL=true`) can be used instead of `DATABASE_URL`. Set `DB_DIALECT=mysql` to point
at MySQL — the same models work on both engines.

## After deploy

- Site: `https://<your-service>.onrender.com`
- Health: `https://<your-service>.onrender.com/health` → `"database":"connected"`
- Swagger (dev only): disabled in production.

| Field    | Value       |
| -------- | ----------- |
| Username | `superadmin`|
| Password | `Admin@123` |

## Caveats

- The filesystem is ephemeral — uploaded files under `uploads/` disappear on redeploy.
  Add a **Persistent Disk** and set `UPLOAD_DIR` to keep them.
- Free PostgreSQL instances expire after 90 days on Render; upgrade the database plan
  to keep data long-term.
- Cron jobs are off by default; keep them off unless the service has a fixed instance
  count of 1 and `RUN_JOBS=true`.
