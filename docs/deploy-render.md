# Deploy to Render

The API and the Angular SPA are combined into a **single web service**: Express serves
`/api/*` and also the built frontend (`index.html`), so the browser talks to one origin
and no CORS/proxy wiring is needed.

## Prerequisites

1. A GitHub repo with this project pushed (already done: `School-Managment-System-`).
2. **An external MySQL 8 database** — Render does not manage MySQL. Free options:
   - Aiven: <https://console.aiven.io> → Add service → MySQL → free plan, then create DB + user.
   - Railway / PlanetScale / Clever Cloud also work.
   Since the service runs on Render's network, use the provider's **public** connection
   details (host, port, db name, user, password) and make sure the host isn't IP-restricted.
   MySQL must allow remote connections (usually yes for these providers).
3. Redis is optional — caching degrades gracefully without it.

## Option A — Blueprint (recommended)

1. In [dashboard.render.com](https://dashboard.render.com), click **New → Blueprint**.
2. Pick the `School-Managment-System-` repository.
3. Render reads `render.yaml`, creates the `sms-api` web service and starts the build
   (`bash render-build.sh` → Angular build, then backend build).
4. Before/after the first deploy, in the service **Environment** tab fill in the real values
   for the database keys created by the blueprint:
   `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS`.
5. Trigger a redeploy. First boot creates the schema (`sequelize.sync`) and seeds defaults.

## Option B — Manual web service

1. **New → Web Service**, connect the repo.
2. Name: `sms-api`; **Runtime**: Node; **Region**: any.
3. Build command: `bash render-build.sh`
4. Start command: `node backend/dist/server.js`
5. Add the environment variables (same keys as `render.yaml`), including `DB_*`.
6. Health check path: `/health`.
7. Deploy.

## Environment variables

| Key                   | Required | Notes                                    |
| --------------------- | -------- | ---------------------------------------- |
| `DB_HOST/DB_PORT/…`   | Yes      | Your external MySQL connection           |
| `DB_NAME`             | Yes      | e.g. `school_db` (must exist)            |
| `DB_USER` / `DB_PASS` | Yes      | MySQL user (all privileges) + password   |
| `JWT_SECRET`          | No       | auto-generated by blueprint              |
| `JWT_REFRESH_SECRET`  | No       | auto-generated by blueprint              |
| `RUN_SEEDERS`         | No       | `true` runs the default seeders          |
| `RUN_JOBS`            | No       | `true` runs cron (single instance only)  |
| `REDIS_HOST`          | No       | leave blank if no Redis                  |
| `SMTP_*`              | No       | for password-reset emails                |

## After deploy

- Site: `https://<your-service>.onrender.com`
- Health: `https://<your-service>.onrender.com/health`
- Swagger (dev only): disabled in production; enable by unsetting `NODE_ENV=production` in the
  `app.ts` guard if you want `/api-docs`.

## Caveats for the free plan

- The filesystem is ephemeral — uploaded files under `uploads/` disappear on redeploy.
  On a paid plan, add a **Persistent Disk** mounted at a path and set the env var
  `UPLOAD_DIR` to that path (the code already reads it).
- Free services sleep after inactivity; the first request after wake-up is slow.
- Cron jobs are off by default; keep them off unless the service has a fixed instance count
  of 1 and `RUN_JOBS=true`.
